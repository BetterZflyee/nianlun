# 年轮 2.6 界面参考与实现边界

本轮将 Three.js 用在项目工作台的空间概览，同时保留普通 HTML 卡片、列表、搜索、按钮和表单。目标是让项目入口更有层次，具体工作仍可直接操作。未以 GitHub 热度、宣传效果或设备帧率作为已验证结论。

## 采用的官方参考

| 参考 | 对本轮的启发 | 年轮中的实现 |
| --- | --- | --- |
| [Three.js：按需渲染](https://threejs.org/manual/pages/rendering-on-demand.html) | 没有画面变化时不必持续渲染；交互或尺寸变化时请求新帧。 | 减少动态效果或用户暂停时按交互重绘；隐藏标签页或离开视口停止持续动效。开启环境动效时设最高 30 FPS。 |
| [Three.js：释放对象](https://threejs.org/manual/pages/how-to-dispose-of-objects.html) | 图形资源需要显式释放，不能只删除画布。 | 退出概览时取消动画、移除事件和观察器，释放几何体、材质和渲染器；上下文丢失时转为项目按钮。 |

本轮复用仓库已有的 Three.js 0.186.1 本地文件。ECharts 继续负责项目关系桑基图，没有为了首页新增第二套关系推断或外部服务。

## 视觉与信息如何对应

- **深绿立体概览**：延续年轮背景与顺丰红强调；轮廓有空间深度，但不把它画成被截断的实体树干。
- **真实项目节点**：节点来自项目标识，位置确定，不按随机数每次重排。颜色使用项目已有状态，不推断进度。超过显示数量上限时提示范围。
- **独立的信息层级**：概览负责识别与进入，统计负责定位待处理范围，卡片/列表负责检索，最近轨迹负责接续已有记录。
- **选择即反馈**：工作流在提交前显示项目、能力和宿主的组合，避免只展示静态流程装饰。
- **逐步展开控制**：记忆图高级控件默认收起，需要调整时再展开，搜索与正文阅读保持可达。

空间轮廓、星尘和动效均为装饰；它们不表示项目依赖、真实增长速度或完成度。项目关系仍只使用原表中的明确关联，记忆关系仍只使用读取到的实际引用。

## 可用性与性能边界

概览最多显示 40 个项目节点，像素比最高 1.75，持续动效最高 30 FPS。以上是代码中的上限，不是性能测试结果。项目集合不受概览节点上限影响；没有 WebGL 时仍能通过项目按钮、卡片和列表进入工作。

系统减少动态效果设置、用户暂停、页面可见性和视口观察共同控制动画生命周期。暂停动画不修改调度和业务状态，切换页面应释放资源。测试应覆盖降级入口、键盘访问、快速切页和实际浏览器显示，不能由模型单元测试替代。

本轮文档不宣称完成真实账号的采集、报告写回或 Windows 原生端到端验收。实际执行证据统一记录在 [2.6 验收记录](VALIDATION_2.6.md)。组件入口与维护方式见 [图表组件](CHART_COMPONENTS.md)。
