# 年轮 2.9.2 发布说明

发布日：2026-11-06。修订版本，不含架构或数据契约变更。

## 这一版解决什么

三个会让主流程直接中断的缺陷，加上一批测试与跨平台修复。此前 v2.9.1 已装进生产但从未发版（68 个提交无标签），本版是这些改动第一次形成可回退的正式版本。

## 三处阻断级缺陷

### 1. 记录写入完全不可用

11-02 的表结构改版把反馈记录表的「详情」列换成了「解决方案」，但代码仍硬性要求 `description`。结果任何「把沟通归集成项目记录」的动作都在生成计划阶段抛错——这是产品的核心能力。

本版让详情列按 `description → solution → notes` 回落，并让幂等去重标记跟随同一个列，避免「写进去了但去重认不出」造成重复入库。

真实配置实测：`plan()` 从抛错变为成功产出 6 字段写入计划。

### 2. 首次发布必然崩溃

`growth.py:804` 取 `now.get('report')` 时 `now` 还没赋值（要到 832 行）。Python 作用域规则下这是必崩，不是概率崩。改用回执里已有的 `previous_link`。

### 3. 写回失败后无法安全重试

写主表前没有登记 `in_flight`。若写接口已生效但响应丢失，重试会重复上传报告，或把「自己刚写的链接」误判成「他人更新」而拒绝。

## 自动生长不再因体量放弃

### 证据按预算裁剪

超 600KB 时原实现直接终止本轮，同一条证据每轮都失败直到放弃。73 个历史 run 里 37 个（51%）超限。

现在按固定优先级收缩：历史记录 → 来源累积 → （单条超长来源不截断，交回宿主）→ 字段契约最后才动。每次裁剪写 `evidence-trim.json` 留痕。

结果：超限 37 → 0，最大 1.82MB → 595KB。

### 证据纯度（「计划内容变更」的真根因）

`prompt_evidence` 浅拷贝证据，`trim_evidence` 裁剪时原地改写超长 source，污染原 bundle——plan 记的哈希是脏的，apply 用干净证据校验必然不等。现在先 deepcopy。

### 自适应裁剪第五级

四级做完仍超预算时继续减半来源，直到进预算。实测 317,940 → 244,094。

### 汇报失败不再拖垮整轮

汇报是收尾步骤，前面写表建待办都已落库。它异常时会把整轮标记为失败，执行记录分不清「主体成功、汇报未出」。现在捕获并写进 `reports_error`，主体照常返回。

### 积压过久限制回看

采集水印落后时不能一次回溯到底——单轮证据会撑爆上下文，而每轮失败又让水印永不前进，形成死锁。现在有 `max_lookback_days`（默认 7）上限，逐轮追赶。

### 模型没返回正文时重试

模型偶尔不按 schema 返回 `answer`，原实现直接拿 None 把报告崩掉。现在判空重试两次。

### source_id 少两个等号就作废整轮

钉钉消息 id 末尾 `==` 是 base64 填充，模型引用时常截掉。原实现严格等值，6 个动作全作废还连累重试。现在只容忍填充符数量差异，不做模糊匹配。

### 只读调用可重试，写操作不重试

10 次失败都发生在会话第一句身份核验上——一次瞬时抖动整轮作废。现在只读调用重试 3 次带退避；写操作仍只发一次，因为结果未知时重发会重复建记录。登录失效快速失败。

### 重试能改到点子上

原来无论校验因为什么失败，重试提示都只说「引用不对」。真实原因若是场地编号错或单选项越界，模型就被推去改引用，三次用尽整轮作废。现已回传真实原因并附上一稿 actions 供定位。

### 合并场地编号

场地表把 `591W` 与 `591WA` 合并成一条（编号 `591W&591WA`），而消息、ASR 与模型输出常只说一半。现已支持复合编号并把任一半边归一到合并编号。

### 字段契约送达

`table_fields` 因取错层级恒为空，提示词里「单选取值必须来自 options」从未生效。修复后真实 run 拿到 11/17/7/12 个字段定义。

## 渲染与样式

- **CSS 注入防嵌套**：外部 recap skill 的样式表自带 `<style>` 块，再包一层会被浏览器丢弃整块，页面变裸 HTML、SVG 回退黑色块。现在注入前剥离标签。
- **增强幂等**：`report_blocks.enhance()` 与 `report_visual.enhance()` 重复执行不再叠加脚本和 CSP 摘要。

## 跨平台

- **Windows ARM64**：`platform.machine()` 在 Windows on ARM 返回大写 `ARM64`，原映射表只有小写，会被判为「不支持的 CPU」拒绝安装。现统一折叠小写。
- 新增 `test_platform.py`：平台键、可执行后缀、`.cmd` 中间层跳过、原生对话框选择、文件锁 import 守卫、路径可移植性。

## 调度

连续失败触顶标记 `abandoned` 后，恢复成功不再通知。现纳入恢复通知名单。

## 未验证的部分

诚实边界，以下仍然待验：

- **Windows 真机**：只有平台分支的隔离测试，没有原生 x64/ARM64 实机安装与业务闭环。
- **Claude Code / WorkBuddy 端到端**：命令与登录已检查，实际推理闭环未验。
- **生产调度恢复**：本版修好了会阻断的缺陷，但旧管线 `battle-pipeline` 是否卸载、新 `nianlun.tick` 是否接管，需负责人确认后执行。

## 升级与回退

升级保留个人配置、四表数据、报告回执与去重记录，只替换核心代码。

回退到 `v2.9.0`：先暂停自生长并等写入结束，在侧栏「版本与回退」退出本机服务，下载 v2.9.0 安装包并核对 SHA-256，运行安装器后用「打开年轮」重启。原核心进入安装目录 `backups`。不要清空运行目录，不要通过删回执重跑旧任务。
