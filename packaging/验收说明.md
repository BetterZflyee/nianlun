# 年轮 0.5.3 验收说明

本包包含独立年轮核心、Mac / Windows 安装器、多个宿主入口和同一套数据与执行契约。业务数据不随安装包分发。

0.5.3 统一产品表述为“独立记忆空间”，沿用现有记忆引擎与数据格式。0.5.2 新增的 4 项发布测试继续执行：公开源码检查、私人内容拒绝、允许文件范围、可重复构建与包内校验及干净目录重复注册。下方业务验证继承 0.5.1 的验收记录；GitHub CI 的跨平台隔离测试结果以相应提交的实际检查为准，不等于真机账户全链路验收。

## 本次验证

- 119 项自动检查通过，覆盖原有表结构、DWS 写入验证、待办联动、报告恢复与页面安全，以及新增的宿主选择、无隐式 Codex 兜底、交接结构校验、原证据冻结、旧配置回答拒绝、页面恢复、跨宿主时段去重和旧调度路径兼容。
- 干净临时目录安装独立核心，没有创建 Codex 目录；仅注册 Claude 入口后可启动，重复安装可用。
- 页面实际选择 WorkBuddy，保存接续模式并生成可读接入说明；没有把说明生成为“已启用原生客户端”。
- Claude Code 本机版本和登录状态检查通过；真实的无业务数据推理测试超时，因此本次未确认模型推理成功。命令构造、标准输出解析和工具隔离通过自动检查。
- 原有 Mac 验证包括：私有运行环境与 GBrain、隔离 AI 表格初始化、页面本人待办完成与关联记录联动、阶段汇报上传与回填、Codex 原生工具工作流与文件产物、GBrain 基线全文检索、原生 heartbeat 注册和非到期空运行。

新增验证覆盖：按来源成功水位与失败补采、48 小时听记回看、跨平台分页和逐字稿路径校验、同项目相近待办拦截、真实回执计数、未完成动作禁止提交水位、空轮低打扰及相同缺口不重复推送。飞书当前账号的真实只读列表重试后成功返回 0 条；不会将该空结果标记异常。带实际逐字稿的飞书全链路用隔离夹具验证，尚待有产物时实测。

## 验证界限

WorkBuddy 和 DeepSeek Harness 的结构化接续协议使用隔离夹具验证，尚未在这两个客户端完成实际端到端测试；未发布官方市场连接器。Claude Code、WorkBuddy、DeepSeek 的原生周期调度需分别在宿主创建与回读；本版不会用自制回执宣称已注册。

Windows 提供启动器、依赖选择和路径实现，尚未完成原生 Windows 真机端到端验证。任意第三方 Skill 的全部外部服务也不在本次验证范围内。

核心只监听本机。项目管理需要用户自己的钉钉登录；AI 分析需要所选宿主可用，自动生长还需要定时负责人实际唤醒。来源覆盖取决于账号权限和 DWS 返回，缺口会明确显示。
