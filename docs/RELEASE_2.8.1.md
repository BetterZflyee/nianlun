# 年轮 2.8.1：报告生成与重试修复

报告已经生成，却因为开头的中文冒号被拒绝，重试还重复使用同一份被拒正文。本次修订消除这类格式死循环，同时保留长度、引用编号和安全内容检查。

## 生成流程

1. 读取项目事实和相关记忆，预检选定的报告渲染环境。
2. 调用所选宿主撰写。兼容 `Lead：` / `Lead:`、大小写、强调、BOM 和外层 Markdown 包装；已存在的开头判断段自动标记，不补写结论。
3. 内容不合格时，每轮最多修订两次。仍不合格会显示具体原因，保留原稿；用户重试后开始新的修订。网络中断继续原请求，不重复丢弃材料。
4. 使用所选 Skill 生成页面和编辑层，确认输出完整后发布。下游失败可继续使用已合格正文。
5. 上传并核验项目主表链接。上传已成功则复用原回执，已写回但响应丢失时回读确认，不重写相同链接，不覆盖其他人后来更新的链接。

当项目事实已变化，原稿不能当作最新结论继续发布。页面会给出“按最新资料重新生成”，保留旧任务和旧稿。失败时明确显示已停止，不再提示后台仍在继续。

## 版本与范围

这是 2.8 系列缺陷修订，v2.8.0 原样保留。没有迁移表格或记忆，没有改变宿主、授权来源或调度状态。输出仍遵循用户选定的 `transcript-visual-recap` 引擎 B；该个人 Skill 不打入公开安装包。

修复不保证模型永远成功：宿主登录、网络、额度、来源读取和事实冲突仍可能中断任务；系统保留材料和回执，给出具体原因与可恢复路径，不用空报告假装成功。验收见 [2.8.1 验收记录](VALIDATION_2.8.1.md)。
