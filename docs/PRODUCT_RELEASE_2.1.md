# 年轮 2.1 产品发布说明书

版本：2.1 · 2026-10-20

程序：2.1.0 发布候选；上一版发布材料：2.0。旧版全部保留。

## 这次要讲清楚的一件事

**项目一直在推进，AI 应该主动跟上。**

每天，群里出现新的结论，会议调整了下一步，邮件确认了交付时间。项目已经变了，AI 却仍然等着我们把变化重新输入。这是年轮想解决的核心问题。

年轮围绕持续进行的工作，自动获取信息、更新项目状态、倒排里程碑、维护记忆并生成汇报。它可以接入不同 AI 宿主，项目数据仍在用户自己的 AI 表格，长期上下文仍在自己的独立记忆空间。

## 三项核心能力

### 自动生长：工作发生了，项目就应该跟着更新

定时获取和手动补采使用相同的处理链。手动可以指定时间、渠道和项目；来源包括已开启的听记、群聊、单聊、邮件与宿主人类会话。年轮理解变化、校验依据，把进度与行动接回对应项目。

来源不完整会保留缺口，相同内容会去重，写入后核验结果。发生了什么、系统具体做了什么，都能回到执行记录查看。

**转场：** 信息跟上了，下一步还要知道——离最终交付还有哪些节点？

### 自动倒排里程碑：给出目标和日期，长出推进路径

用户填写可验收的项目目标和目标日期，年轮规划交付节点与前置关系，按最终日期倒排。开启自动倒排后，计划会随新事实调整。

人工节点、已完成节点及人工修改保留。计划与完成事实分开记录；不会因为“时间到了”就假定“事情做完了”。用户不需要先手工设计完整节点表，仍然保留对目标与取舍的决定权。

**转场：** 当每天的进展都能对上节点，阶段汇报便有了持续积累的依据。

### 自动汇报：进展与节点持续积累，报告随之生成

年轮组织目标、本期进展、节点变化、风险与下一步，区分实际发生、未来计划和缺失证据。不要求人先补齐一份正文才开始。

汇报支持固定周期、生长后自动更新和手动时间范围。生成后上传至用户文件夹、回填主表链接；需要组织推进时，可预览并通过 DWS CLI 发送到明确选择的项目群。人的修改是可选的判断与表达，不是系统工作的前置条件。

**转场：** 这些能力要落在每天真正会打开的页面里。

## 日常工作中的配套能力

| 能力 | 用户可以做什么 | 与主线的关系 |
| --- | --- | --- |
| 项目工作台 | 查看项目记录、场地和节点；手动获取进度；生成阶段或月度汇报；选择项目群发送 | 把生长结果用于推进 |
| 独立记忆空间 | 自动维护项目事实和计划，保留每轮档案，随时检索 | 让上下文随着工作积累 |
| 能力中心 | 指定多个 Skill 文件夹，扫描后选择启用，包括 Codex / Claude 目录 | 把已有方法带入项目 |
| 工作流 | 带着项目背景执行具体任务，沿用宿主权限或交回宿主接续 | 从理解走向具体动作 |
| 我的待办 | 读取丰声 / DWS 可见待办，在页面确认完成并回写；有明确证据时自动闭环 | 让行动状态跟上事实 |

## 不到 15 分钟的发布节奏

正式材料保留 14 页，安排约 8 分钟讲述与视频、3 分钟演示、1 分钟切换，另留余量。具体时长以 2.1 逐页讲稿为准。

1. 开场与共同痛点：从“我们已经在用 AI，项目为什么仍需人盯着同步”进入。
2. 先播放 26 秒产品短片，让观众看到产品。
3. 一页总览三项核心能力，随后逐项展开生长、里程碑、汇报。
4. 用同一个示例项目串联演示，展示已有结果，不现场等待长任务。
5. 说明记忆维护、Skill 与待办如何服务于持续推进，简述数据自有与宿主选择。
6. 邀请观众带一个真实项目参与体验，收束到“你继续往前，年轮持续跟上”。

不另设“产品揭幕”环节，不在台上逐步培训安装流程，不讲大量接口或权限细节。每一部分的结尾为下一部分铺垫，不把功能堆成菜单。

## 发布口径与验证边界

- 2.1 已实现上述页面入口与核心处理链，自动化测试使用隔离数据和模拟云端，不向真实同事群发消息。
- 新增邮件、选定群聊及真实账户下的自动倒排 / 连续汇报，仍需按明确的项目、邮箱、群与目标日期进行集成验收。
- 旧有 Mac + Codex 链路已有实测；Windows、Claude 完整推理、WorkBuddy 与 DeepSeek 原生客户端分别保留待验收项。
- “自动”指在授权范围、开启的动作和运行条件内自动执行。来源或宿主不可用时会显示缺口或等待，不编造成功。
- “非侵入式”指核心与宿主入口分离，不接管宿主全局配置和权限；并非不需要登录、连接或本机运行环境。
- 2.1 是增量迭代，大版本留给里程碑。此次不发布 3.0，也不重命名旧版。
