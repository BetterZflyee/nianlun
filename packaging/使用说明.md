# 年轮安装版 2.7.1

年轮是一套可以接入不同 AI 应用的项目记忆与自动生长系统。工作台、项目流程与去重回执由年轮管理；AI 宿主提供理解和执行能力；业务数据保存在你自己的钉钉 AI 表格和独立记忆空间。

## 第一次使用

1. 解压安装包。Mac 双击「安装年轮.command」；Windows 双击「安装年轮.cmd」。不要求先装 Codex，安装器会准备个人运行环境、钉钉连接工具与记忆引擎，并打开页面。
2. 登录自己的钉钉账号，粘贴 AI 表格链接。初始化年轮四张子表，或将已有子表和字段对应到年轮用途。先检查方案，已有数据保留。
3. 新建独立记忆空间或连接已有记忆库。没有安装过也可选新建，无须另买模型服务或输入 API Key。
4. 选择 AI 宿主：Codex、Claude Code、WorkBuddy、DeepSeek Harness 或其他应用。CLI 模式复用已登录的宿主；接续模式生成接入说明，在该宿主里继续。年轮不替你创建模型账号或修改宿主权限。
5. 选择信息来源、自动动作、时区和时间，再选择一个定时负责人。AI 宿主与定时负责人可以不同；换 AI 宿主不会自动切换定时任务或扩大来源。

也可把完整安装包交给你的 AI 应用，按「在AI宿主中安装.md」执行。普通用户不用改代码或 JSON。

以后双击「打开年轮」，或对已接入的 AI 应用说“打开年轮”。不要直接打开 assets/portal/index.html；它是页面文件，误开时会提示正确入口。

## 2.7.1 工作台调整

能力中心、工作流和执行记录移除 Three.js 图景，直接显示能力分类与列表、配置表单、执行记录筛选与详情，不恢复旧版流程图。原有搜索、批量管理、工作流提交、记录详情、重试与接续操作继续使用。

项目工作台、项目关系、待办、项目记忆和接入与运行保留现有可视化。待办点项目筛选列表，接入页点节点定位配置；项目关系只连接已有的记录关联。编辑和批量操作仍通过列表与表单完成。

记忆星图从全景进入项目范围，再沿已读取的真实引用阅读正文，默认关闭自动漫游。保留的任务图景默认静止，可拖动旋转、滚轮缩放、复位或收起；键盘可从图下方按钮选择条目，WebGL 不可用时使用轻量目录。

图中数量只代表当前已载入范围。“已配置”不代表登录或连接健康已核验。升级保留数据绑定、宿主、来源授权与运行回执，不恢复暂停的定时任务。完整操作、修订范围和回退方法见安装包中的 `docs/USER_GUIDE.md`、`docs/RELEASE_2.7.1.md` 和 `docs/VERSIONING.md`；2.7.0 安装包及发布文档保留作为直接回退版本。

## 不同宿主如何协作

| 宿主 | 分析与生长 | 工具工作流 | 定时任务 |
| --- | --- | --- | --- |
| Codex | 页面直接调用已登录 CLI，或宿主接续 | 页面执行并展示单次审批 | 原生控制器注册和回读验证 |
| Claude Code | 页面调用已登录 CLI，或宿主接续 | 在 Claude Code 原生界面执行 | 在宿主中配置并核验 |
| WorkBuddy | 通用 Skill / CLI 接入，结构化接续 | 在 WorkBuddy 中执行 | 按该应用真实能力配置并核验 |
| DeepSeek Harness | 通用 Skill / CLI 接入，结构化接续 | 在所用 Harness 中执行 | 按具体 Harness 能力配置并核验 |

“在宿主中接续”表示：年轮保留证据和结构化请求，由你正在使用的 AI 应用分析；结果返回后，年轮继续去重、写入和回读。页面执行记录会显示“等待宿主”，可以复制接续请求，并在宿主回复后继续原任务。不会暗中调用另一个应用兜底。

WorkBuddy、DeepSeek 的通用交接协议已提供；未声称已完成这两个原生客户端的端到端验收或官方市场上架。没有本地命令执行或周期调度能力的宿主，会保留相应待接入状态。

## 数据、来源和非侵入式边界

项目、里程碑、场地与记录保存到自己的 AI 表格。长期记忆在自己的独立记忆空间。本机只保留连接设置、证据、产物、游标和去重回执，不建立另一套项目数据库。

年轮不修改宿主源码、系统提示、账号、权限或 MCP 设置。安装时只注册用户选择的 Skill 入口，其他应用通过接入材料导入；不扫描未知宿主的私有会话库。

来源独立选择：钉钉听记、飞书本人拥有的妙记（可选，需已安装并登录 lark-cli）、群 @我、单聊、Codex 人类会话、其他宿主主动交付的人类会话、工作台已完成工作流的人类请求。Codex 会话开关表示读取本机该账号的会话，不仅是年轮聊天；其他宿主只读取用户启用并交付的标准输入。

## 自动生长

默认业务时间为每天 10、12、14、16、18、20 点，周四 9 点阶段汇报；在页面选择自己的时区和时间。宿主每小时唤醒核心检查，无到期任务返回 idle，暂停时返回 paused。电脑和负责唤醒的宿主需要可用。

同一工作空间只设一个定时负责人。迁移先停止并核验旧任务，再接入新的宿主。所有入口共用锁和去重回执；电脑睡眠后最多补跑最近一天内各一轮生长与汇报。待交接或失败的旧轮次先恢复，未知云端写入先对账。

Codex 的原生任务可以由年轮回读验证。其他宿主需通过其真实原生接口创建和回读；本地仅记录“待宿主验证”和最近一次收到唤醒的时间，生成说明或单次运行不算已启用周期调度。

听记与妙记每轮滚动补采最近 48 小时，页面可选 24 小时至 7 天。每个渠道单独记录成功进度与补采窗口；失败不标记为已处理。执行记录同时展示定时轮次、扫描数和完整性。连续空列表只计数，不根据“昨天有会议”猜测今天故障。

摘要提供“每轮”和“仅变化时”两种模式；旧安装沿用原推送方式。实际新增、完成、更新和复用数量从写后回执产生；项目研判与执行结果分开呈现。

旧听记脚本合并到统一控制器的步骤见 `skills/nianlun/references/controller-migration.md`。现有旧脚本与年轮不能作为两个并行写入器运行。飞书不是首次安装必需依赖，未启用时不调用、不要求登录；启用后使用当前飞书用户身份。

## 程序与移植

独立记忆空间当前由 GBrain 引擎提供。连接已有空间需使用兼容的 GBrain 工作目录；接入细节见 `skills/nianlun/references/memory-space.md`。普通用户选择创建新空间即可，由安装器准备依赖。

- 核心：~/.local/share/nianlun/core/nianlun。
- 安装记录与运行环境：~/.local/share/nianlun。
- 个人工作空间：~/.config/nianlun；自己的运行回执位置见配置。
- 新建独立记忆空间：~/.local/share/nianlun/memory；已有库保留原位置。
- 各宿主入口只指向同一核心。旧版 Codex 入口作为兼容转发器保留，现有控制器无需因升级重新创建。

Windows 的 ~ 指本人用户目录。对外分发 ZIP 不包含账号、表 ID、项目数据或记忆。换宿主无需复制业务数据；换电脑需重新登录，连接原表格并迁移或接入独立记忆空间，需要连续恢复时同时迁移个人配置和回执。升级保留这些内容；卸载前先停用本安装的定时任务。

Mac 启动器尚未签名，可交给 AI 宿主安装，无须关闭系统防护。Windows 尚未完成原生真机端到端验证。具体真实验证范围见「验收说明.md」。
