# 2.1.1 修订发布候选验证记录

日期：2026-10-21。基线：2.1.0；本次不修改业务表结构，不增加来源或开启自动动作。

## 已验证

- 155 项核心自动测试通过，其中新增 25 项暂停、恢复和状态回归测试。提供方操作使用隔离夹具，不向真实表格写入、不创建真实待办、不发送消息。
- 原生任务 PAUSED 时，工作台显示已暂停；无效任务不视为已接入。状态回读不覆盖旧注册凭证。
- 已有未完成轮次时仍能立即暂停，暂停不经过业务写入队列，不改变冻结配置；手动恢复保持暂停。
- 模拟“写入成功、返回丢失”：按原来源标记、真实编号及字段回读后继续剩余步骤；多动作计划不会漏掉尚未开始的动作。
- 已完成待办不重复关闭；待办被人工重新打开时停止恢复。创建待办没有原编号、摘要没有投递句柄、记录有冲突或重复标记时保留待核。
- 记忆按原 slug 与完整原正文回读；配置、身份或轮次变化时拒绝恢复。
- 整轮恢复经过 collect / apply / finish，保留原轮次，写回完成回执并生成离线工作台；不启动新轮次。
- 相同失败的通知标识不变时 notify=false；原因变化或恢复时 notify=true。原失败时段保留重试次数，恢复后更新为完成。
- 页面、离线快照、批量汇报和自动规划共用活跃项目判定；派生 active 字段不进入历史业务事实哈希。
- 两份页面 JavaScript 通过语法检查；隔离浏览器验收原生暂停、只读核验后出现继续按钮、未完成轮次下立即暂停。页面恢复不会替用户启用原生调度。
- 发布与安装包 4 项检查：公开文件允许范围、私人内容模式检查、可复现 ZIP 与逐文件哈希、中文空格路径中的干净目录重复注册。不创建未选择的宿主目录。

- 本机升级至 2.1.1，原配置、原生任务与待核验轮次共 13 份关键文件哈希未变；保留旧核心和安装记录，页面回读原生状态为暂停。
- 针对真实表格新增状态选项的兼容检查：保留原绑定，允许单选字段增加选项；删除、改名或类型变化仍拦截。页面使用回读的选项，避免把新值显示成其他选项。维护者真实四表已只读验证恢复，未修改表结构或业务记录。

## 验证边界

- 未对维护者的真实未知写入自动认定成功或重放；原待核验记录保留。
- 本次修复在 Mac 及隔离数据上验收。Windows 原生安装、其他宿主客户端及真实网络异常下的完整业务链仍需专门集成验收。
- “暂停”停止启动后续定时轮次，不强行撤回已提交的写入或中断当前动作。
- notify 是控制器提供给宿主的通知信号；宿主应遵守此信号，不能把相同的历史错误当作新变化重复汇报。
- 发布候选不等于已公开 GitHub Release；公开发行仍按 RELEASING.md 核验目标提交的 CI 和附件。

2.1.0 的验收记录、安装包和发布材料保留原名，不覆盖历史版本。
